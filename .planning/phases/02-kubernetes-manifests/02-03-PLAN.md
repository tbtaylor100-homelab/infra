<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| k3s node → ghcr.io | Image pull from GitHub Container Registry; must be reachable from cluster |
| pod → OpenBao (via ESO) | ExternalSecret syncs at refresh interval; pod env vars set at startup from k8s Secret |
| LAN device → MetalLB IP | All LAN devices can reach 192.168.1.205:3000; no authentication on AIOStreams (intranet-only per REQUIREMENTS.md) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Availability | ESO sync (ExternalSecret → pod startup) | mitigate | Verify ExternalSecret READY: True before pod starts. Pod will CrashLoopBackOff if aiostreams-secret doesn't exist — this is intentional fail-fast behavior. Fix: wait for ESO sync or check eso-policy scope. |
| T-02-09 | Information Disclosure | kubectl get secret output during verification | accept | kubectl describe/get secret shows base64-encoded data, not plaintext. Operator access to cluster assumed trusted. Avoid piping secret data to logs. |
| T-02-10 | Availability | Image pull from ghcr.io | accept | ghcr.io is a public registry for a public image; no auth required. If pull fails (network issue), imagePullPolicy: IfNotPresent means second attempt uses cache. Low risk in homelab. |
| T-02-11 | Availability | SQLite database on first start | accept | First-start SQLite initialization creates /app/data/db.sqlite on the PVC. If PVC is not yet Bound at pod start, pod enters Pending — resolves automatically when local-path provisions the volume. No data loss risk on first start. |
</threat_model>
